# Список существующих и потенциальных проблемных мест
* Открытый доступ к MES API
* Единая БД Интернет Магазина и CRM
* Отсутствие кеширования 3d моделей, списка заказов MES
* Долгая загрузка первой страницы MES сервиса
* Теряются заказы клиентов
* Место потери заказов неизвестно
* Частые задержки релиза
* Недостаточная квалификация FrontEnd разработчика для Mesh сервиса
* Отсутствие мониторинга, логирования и трейсинга.
* Один инстанс БД Shop DB
* Отсутствуют автотесты
* Проблема производительности MES API: не оптимизированный процесс рассчета стоимости, т.к. сервис выполняет рассчеты и обрабатывает API запросы, время обработки запроса может быть сильно увеличено, либо запрос не обработан из-за высокой нагрузки на сервис. Необходимо выделить из сервиса API и организовать асинхронное взаимодействие через RabbitMQ 
* Долгий процесс деплоя
* Задержки в релизах
* Ручной деплой в release и prod
* Нет ограничений на кол-во запросов к MES API для внешних пользователей
* Единая точка входа для внутренних внешних пользователей MES API

* Внедрить мониторинг, логирование и трейсинг

* Вынести в отдельный сервис загрузку файлов
* Выделить из MES сервиса расчет стоимости изделия в отдельный сервис
* Масштабировать MES API и новый сервис расчета стоимости изделия
* Разделить БД Интернет магазина и CRM
* Настроить репликации для всех БД
* Внедрить кеширование для MES сервиса
* Внедрить автотесты
* Настроить интеграции между сервисами через брокер сообщений
* Внедрение версионности API
* Внедрения нотификации
* Оптимизация процесса тестирования и деплоя

# Инициативы в порядке приоритета
## Целевая архитектура через пол года:

* Интернет Магазина и CRM используют разные БД
* Настроены репликации БД сервисов
* Сервис расчета стоимости изделия выделен в отдельный сервис
* API сервисов скрыты за API шлюзом
* Внедрены мониторинг и логирование сервисов
* Сервис MES API масштабирован
* Добавлено кеширование для MES сервиса
* Реализована асинхронная модель взаимодействия между сервисам

## Инициативы:
* Формирование команды разработчиков, выделение отдельных команд по сервисы, т.к. на текущий момент команда работает над всеми сервисами, состав команды и их квалификация не позволяет качественно выпускать релизы. Позволит сократить время на релизы
* Разделяем сервисы Интернет Магазина и CRM, с разделением БД и настройкой репликаций БД - открывает возможность к масштабированию сервисов, с увеличением производительности и отказоустойчивости.
* Внедрение API шлюза - необходим для внедрения масштабируемости и безопасности системы
* Внедрены мониторинг и логирование сервисов - в текущей реализации система не наблюдаема, найти узкие и проблемные места проблематично, с внедрением данной инициативы система становится наблюдаемой
* Выделение стоимости расчета изделия в отдельный сервис позволит масштабировать отдельные компоненты системы и повысить отказоустойчивость и безопасность системы и отдельных ее компонентов.
* Внедрение кеширования позволит уменьшить время и стоимость работы сервиса
* Автоматизация процессов CI\CD

## Три основные инициативы:
* Формирования команды разработчиков, автоматизация CI\CD
* Внедрение мониторинга, логирования и кеширования
* Горизонтальное масштабирование
